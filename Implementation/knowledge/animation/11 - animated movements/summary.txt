Processus chronologique de développement
Étape	Description
1. Préparation des animations	Téléchargement sur Mixamo de 3 animations (idle, marche, course), conversion en animations humanoïdes et import dans Unity.
2. Configuration du personnage	Import du modèle Jammo, conversion en humanoïde, ajout du contrôleur d’animation (Animator Controller) avec états idle, walk, run et leurs transitions basées sur des booléens isWalking et isRunning.
3. Mise en place du nouveau système d’input	Création d’un asset “Player Input” avec un Action Map “CharacterControls” contenant des actions Move (type Vector2) et Run (type bouton). Configuration des bindings clavier (WASD + Shift) et manette (joystick gauche + bumper gauche).
4. Programmation des callbacks d’input	Déclaration d’une instance PlayerInput, activation/désactivation des maps d’actions dans les méthodes OnEnable/OnDisable, utilisation des callbacks started, performed et canceled pour gérer la saisie.

Concepts clés et définitions
Terme / Concept	Définition / Usage
Character Controller	Composant Unity permettant de gérer le déplacement d’un personnage sans gérer soi-même la physique complète.
Animator Controller	Contrôleur d’animation qui gère les transitions entre états d’animation (idle, marche, course).
Input Actions	Asset Unity regroupant les actions d’entrée, leurs bindings et propriétés dans le nouveau système d’input.
CallbackContext	Objet passé aux callbacks d’input permettant de lire les valeurs de saisie en temps réel.
Vector2 / Vector3	Vecteurs stockant les données de mouvement sur deux ou trois axes.
Quaternion	Représentation mathématique des rotations en 3D utilisée pour des interpolations fluides.
Time.deltaTime	Durée en secondes entre deux frames, utilisée pour uniformiser le déplacement indépendamment du framerate.
Points importants et conclusions
Conversion des animations en format humanoïde est essentielle pour utiliser la structure d’animation mecanim de Unity et permettre la réutilisation sur différents modèles humanoïdes.
L’Animator Controller doit contenir des paramètres booléens (isWalking, isRunning) pour gérer les transitions entre états d’animation.
Le nouveau système d’input Unity permet une configuration flexible avec actions, maps d’actions et bindings adaptables au clavier et manette.
La gestion des callbacks started, performed et canceled est cruciale pour détecter les débuts, mises à jour et fins d’actions d’entrée.
