Retargeting d’animations dans Unity
Cette vidéo, présentée par Nicky, poursuit une série dédiée à l’apprentissage du système d’animation d’Unity, en se concentrant aujourd’hui sur la transfert (retargeting) d’animations entre différents personnages. L’objectif est de comprendre comment utiliser une animation créée pour un personnage sur d’autres modèles aux rigs différents, en s’appuyant sur le système d’avatars humanoïdes d’Unity.

Contexte et Préparation
Téléchargement initial d’un personnage et d’animations gratuites sur Mixamo.
Importation dans Unity de plusieurs personnages :
Un nouveau personnage Mixamo avec animation de saut.
Deux personnages supplémentaires gratuits depuis l’Asset Store ou Package Manager Unity : Jammo (mascotte de la chaîne MixAndJam) et SpaceRobotKyle.
Mise à jour des matériaux pour les rendre compatibles avec les pipelines de rendu URP ou HDRP.
Ajout des composants Animator et création d’un contrôleur d’animation nommé retargetController.
Problématique rencontrée
L’animation de saut fonctionne uniquement sur le personnage Mixamo d’origine.
Les autres personnages ne réagissent pas car les noms des os dans les rigs sont différents.
Renommer les os manuellement n’est pas une solution viable, surtout avec des proportions différentes, car cela génère des résultats déformés.
Solution : Avatar Humanoïde et Rig Humanoïde dans Unity
Unity propose une conversion des rigs génériques en rigs humanoïdes via la création d’avatars humanoïdes. Ce système standardise la hiérarchie des os et permet le partage d’animations entre personnages humanoïdes, même s’ils ont des proportions différentes.

Paramètres clés dans l’onglet Rig :
Option	Description
Animation Type	Quatre choix : None, Legacy, Generic, Humanoid. Humanoid permet la retargeting d’animations.
Avatar Definition	"Create From This Model" ou "Copy From Avatar" : choix de créer ou copier un avatar humanoïde.
Skin Weights	Nombre d’os influençant un vertex (par défaut 4) pour contrôler les déformations du mesh.
Optimize Game Object	Option pour optimiser la hiérarchie des transforms avant publication, mais attention aux bugs.
Configuration de l’avatar humanoïde
Unity tente une auto-assignation des os basée sur les noms standards.
Si les noms ne correspondent pas (ex : modèle Blender personnalisé), il faudra faire un mapping manuel.
L’interface propose des options pour :
Effacer, auto-mapper, charger ou sauvegarder les mappings d’os.
Gérer la pose initiale : Reset, Sample Bind Pose, Enforce T-Pose.
Le menu « Muscle and Settings » permet d’ajuster les contraintes musculaires pour éviter les déformations visuelles, notamment avec des modèles aux proportions extrêmes.
Résultats et utilisation
Conversion de tous les personnages en rigs humanoïdes avec avatars correspondants.
Nécessité de dupliquer les animations après conversion pour qu’elles soient compatibles avec le rig humanoïde.
Après ces étapes, le même saut peut être utilisé sans problème sur tous les personnages humanoïdes.
Notes importantes
Lors du téléchargement d’animations Mixamo sans skin, il est crucial de :
Choisir le même personnage que celui utilisé dans le tutoriel pour conserver la cohérence des noms d’os.
Sélectionner “Copy From Avatar” en choisissant l’avatar téléchargé.
Tous les états d’animation dans l’Animator doivent être convertis en Humanoid pour éviter les conflits.
Modifier le paramètre Root Transform Rotation des animations de “Body Orientation” à “Original” et activer Bake Into Pose pour un rendu correct.
Les connaissances acquises permettent de contrôler via le joueur n’importe quel personnage humanoïde et animation, en combinant avec les techniques des vidéos précédentes.
Conclusion
Cette vidéo démontre l’importance du système d’avatars humanoïdes dans Unity pour faciliter la réutilisation des animations entre personnages différents. En configurant correctement les rigs et avatars, on obtient une interopérabilité efficace des animations, ce qui est essentiel dans le développement de jeux vidéo multi-personnages.
