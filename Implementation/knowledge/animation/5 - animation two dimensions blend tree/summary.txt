Types de blend trees 2D dans Unity :

Type	Description	Cas d’usage principal
2D Simple Directional	Utilise une seule animation par direction, limitation à < 180° entre motions, animations exclusives.	Concepts simples avec peu de motions
2D Freeform Directional	Permet plusieurs animations dans la même direction, sans limitation d’angle entre motions.	Configurations complexes avec plusieurs animations par direction
2D Freeform Cartesian	Calcul différent de l’influence, utilisé pour paramètres non directionnels (ex : angles vertical/horizontal).	Animations comme visées ou autres blends non directionnels
Direct	Contrôle manuel du poids de chaque animation, souvent utilisé pour expressions faciales.	Contrôle granulaire spécifique, souvent manuel

Limites du blend tree 2D simple directional :

Ne blend pas plusieurs animations dans la même direction.
Exclusion d’animations à 180° de distance.
Problème avec l’animation de course latérale gauche/droite.
Conclusion : Simple directional n’est pas adapté à une configuration multi-directionnelle complexe.
Adoption du blend tree 2D freeform directional :

Fonctionne comme attendu avec toutes les animations blendées correctement.
Idéal pour plusieurs animations dans une même direction sans restriction angulaire.
Explication sommaire sur freeform cartesian :

Différence subtile avec freeform directional dans le calcul des poids.
Principalement utilisé pour des animations où les paramètres ne sont pas liés à la direction, exemple : angles de visée.
Complexité mathématique confirmée par une thèse universitaire (niveau avancé).

Résumé des apprentissages et conclusions
La différence entre les types de blend trees 2D tient principalement à la façon dont Unity calcule l’influence de chaque animation selon les paramètres.

Le blend tree 2D freeform directional est le plus adapté pour gérer plusieurs animations dans plusieurs directions simultanément, notamment dans un contexte de déplacement complexe (avant/arrière et strafe).

L’implémentation logicielle nécessite une gestion fine des vitesses, avec accélération, décélération et plafonnement selon l’état du joueur (marche ou course).

Le refactoring est crucial pour maintenir la performance et la clarté du code, surtout dans des scripts de contrôle d’animations complexes.

Prochaines étapes annoncées : retargeting des animations Mixamo vers un autre modèle, arbres d’état d’animation plus complexes, gestion des couches d’animation et événements d’animation.
